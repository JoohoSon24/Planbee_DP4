이슈와 현재 Task context를 읽고 시간 안에 완료할 수 있도록 새 milestone 계획의 구조 template를 최대 12개 설계하라. 각 template의 parts는 보유분까지 원 업무 전체를 정확히 한 번 포함하고 effort 합이 original_task.days와 같아야 한다. 실제로 다른 산출물 what, 고유 key와 선행 depends_on을 명시한다. 순차 조각과 독립 병렬 조각을 구분한다. 담당과 시작 시간 조합은 이후 알고리즘이 확장한다. 분리 금지면 단일 전체 업무만 허용한다. 협업으로 시간을 줄일 경우 support에 실제 지원 산출물·일수·역할·main_ratio·단축 근거를 써라. 지원 일수도 실제 일정으로 계산된다. 생성은 feasibility 전용이며 카드 적합성·부담 분산을 최적화하지 않는다. Hive의 validation_feedback이 있으면 같은 오류를 반복하지 말고 고친 구조를 제출하라. 타당한 구조가 없으면 templates=[]와 reason을 답한다.

Task context의 required_parts가 있으면 key·what·effort와 담당 권한을 그대로 보존하라. allowed_assignees, fixed_start, earliest_start, latest_finish, allow_collaboration=false는 하드 제약이다. 선택 기능의 범위 삭제·Beta 이관·검증 생략·조건부 의존성 교체는 현재 출력 schema로 표현할 수 없으므로 지원되는 것처럼 꾸며 답하지 말고 reason에 필요한 PM 결정을 남겨라.
