# v004_quarter_day_and_exact_budget

가설: 재견적의 6h 반올림과 형식 복구 호출 집계 누락을 재현 테스트로 수정. M4 2h 단위와 실제 호출 예산을 보존하면 T1~T5가 모두 기대한 PM 검토 또는 선택 대기까지 도달한다.

실행 결과는 이 버전의 experiments/ 아래 저장합니다. 실제 Live, Mock, 모의 당사자 승인은 구분합니다.

## 실제 Live와 원본 진단

T2/T3/T4의 후보 제출과 T5 PM 전달은 기준 충족. T1은 같은 6h를 여전히 1일로 재견적해 실패. 테스트 환경만 5/5이며 실제 Live를 그 결과로 대체하지 않았습니다.

추가 1회 원본 진단에서 모델이 days=1.0, basis=“일정 이동만 요청했으므로 소요량을 늘리지 않는다.”, evidence=“Polish 소요량은 6h 그대로입니다.”로 서로 모순된 답을 보냈습니다. 시간 단위 코드만으로는 이를 막을 수 없어, 다음 버전은 duration_changed라는 명시적 의도 판단을 숫자와 분리합니다. 일정만 바뀌면 새 견적을 적용하지 않습니다.

v004의 공유 예산 used 값은 실제 논리적 LLM 호출 수와 일치했습니다(transport 재시도가 없던 이번 실행 기준). 형식 복구 횟수와 출력 실패 횟수도 별도 보존했습니다.
