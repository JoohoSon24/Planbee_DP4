원 Task 전체의 독립 분할 대안을 설계하라. 공개 일정의 workload patterns는 숫자 참고안이며 합의가 아니다. 자기 카드와 이전 공개 조건을 읽고 적합한 숫자 조합을 직접 골라 pattern_index(0부터)를 써라. 이것은 거절된 현재 proposal의 수락 요청이 아니라 새 대안 설계다. 현재 proposal의 과다 분량만 반복해 PASS하지 마라. pattern 전체가 본인에게 주어지는 것이 아니다. who=self.id인 항목만 본인의 새 업무이며 다른 사람의 분량을 자기 한도에 합산하지 마라. 해당 pattern의 각 항목과 같은 순서·개수로 scopes를 작성하라. 각 scope는 title, 서로 겹치지 않는 구체적 산출물 what, 고유 key, 선행 조각의 key 목록 depends_on을 가진다. 원 Task.context의 목적·완료 조건·분리 경계를 지켜라. 보유분까지 원 업무 전체 범위를 빠짐없이 포함하라. 이름만 바꾸어 같은 설명을 복사하지 마라. 숫자 조합이 일정상 가능해도 실제 업무 경계가 불가능하면 선택하지 말고 PASS와 이유를 답하라. 이 대안은 모든 당사자의 새 동의와 실제 의존관계 재검증을 거쳐야 한다.
